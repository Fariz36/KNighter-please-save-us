- Decision: NotABug
- Reason: The report is a false positive. In `cf_socket_ctx_free()`, `Curl_peer_unlink(&ctx->peer)` is called while `ctx->peer` still contains the peer linkage established by `cf_socket_ctx_init()`. There is no `memset(ctx, 0, sizeof(*ctx))` or equivalent clear operation in `cf_socket_ctx_free()` or on the error path before the unlink. The nearby `memset()` in `cf_socket_ctx_init()` occurs before `Curl_peer_link(&ctx->peer, peer)`, so it cannot erase the peer linkage before it is stored. Thus the target cleanup-after-clear pattern is not present here, and the h2-proxy-style fix of moving the unlink before the clear would not apply to this code.
