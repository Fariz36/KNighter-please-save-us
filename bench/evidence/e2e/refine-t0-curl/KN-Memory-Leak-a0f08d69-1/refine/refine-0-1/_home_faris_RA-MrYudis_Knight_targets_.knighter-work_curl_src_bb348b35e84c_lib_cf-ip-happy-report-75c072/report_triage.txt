- Decision: NotABug
- Reason: The report points to `cf_ip_ballers_clear()` in `lib/cf-ip-happy.c`, but that function does not zero the containing `struct cf_ip_ballers` with `memset()` before calling `Curl_peer_unlink()`. The only `memset` on `bs` is in `cf_ip_ballers_init()`, before any `Curl_peer_link()` calls. In the only error path from `cf_ip_ballers_init()` (unsupported transport), it returns before linking any peers, so the embedded `Curl_peer` nodes are still zeroed and never held a reference. Calling `Curl_peer_unlink()` on such zeroed, never-linked nodes is effectively a no-op and does not leak a peer. In the normal path, the peers are linked after the `memset` and later unlinked without any intervening `memset`. Therefore the reported case does not match the target bug pattern of “linked resource is zeroed by `memset()` before being unlinked.” The actual target bug and fix are in `cf-h2-proxy.c`, where `ctx->dest` is zeroed before `Curl_peer_unlink(&ctx->dest)`. This report is a false positive.
