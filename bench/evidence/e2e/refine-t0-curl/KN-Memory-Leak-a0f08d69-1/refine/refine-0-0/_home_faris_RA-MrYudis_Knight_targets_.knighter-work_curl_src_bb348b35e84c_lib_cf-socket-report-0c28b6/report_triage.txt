- Decision: NotABug
- Reason: The reported code in `cf_socket_ctx_free()` does not zero the containing struct before calling `Curl_peer_unlink(&ctx->peer)`. It correctly performs the unlink before `curlx_free(ctx)`. The only relevant `memset(ctx, 0, sizeof(*ctx))` occurs in `cf_socket_ctx_init()`, and it is followed by `Curl_peer_link(&ctx->peer, peer)`, so the peer pointer is properly initialized before later cleanup. The static analyzer likely confused the initialization-time memset with a cleanup-time memset or failed to model that `Curl_peer_link` sets `ctx->peer`. This does not match the target bug pattern where `memset` clears the struct before the unlink in the same cleanup path. Therefore, it is a false positive.
