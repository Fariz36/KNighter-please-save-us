- Decision: NotABug
- Reason: The warning points to `Curl_peer_unlink(&ctx->peer)` in `cf_socket_ctx_free()`, but that function unlinks the peer **before** freeing `ctx` and does not clear/zero the struct first. The only `memset(ctx, 0, sizeof(*ctx))` is in `cf_socket_ctx_init()`, and it occurs **before** `Curl_peer_link(&ctx->peer, peer)` establishes the peer linkage. Therefore, at cleanup time `ctx->peer` still contains the valid linkage, and `Curl_peer_unlink()` can release it correctly. The target bug pattern requires a clear/`memset()` of the struct field **after** the resource is linked and **before** cleanup, as in `cf-h2-proxy.c` where `ctx->dest` is zeroed before `Curl_peer_unlink(&ctx->dest)`. That does not occur in the reported `cf-socket.c` path. Hence this is a false positive and does not match the target bug pattern.
