## Bug Pattern

Missing validation of the UTF-8 leading byte before using the derived continuation-byte count as a shift amount. Invalid leading bytes such as `\xFF` make `count` exceed 5, so `(c & 0x7F) << (count * 5)` shifts a 32-bit value by 35 bits, causing undefined behavior. The `count > 5` check is performed only after this shift, so the unsafe operation already happens. The fix rejects such leading bytes up front.
