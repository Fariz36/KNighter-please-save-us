## Bug Pattern

A GC-managed table is held only through a C local pointer while calling a function that may allocate and trigger an emergency garbage collection. If that table is reachable only via a weak reference, such as a weak metatable’s `__newindex` field, the collector can free it during the call because the C local is not a GC root. The code then continues using the freed table, causing a use-after-free. The fix is to anchor the table on the Lua stack before the GC-triggering operation.
