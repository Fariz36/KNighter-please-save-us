## Bug Pattern

The bug pattern is performing arithmetic on `u32` (unsigned 32-bit) values that can overflow before the result is assigned or implicitly widened to a larger type such as `i64`. In the buggy code, the expression `(pCur->info.nPayload - pCur->info.nLocal + ovflSize - 1) / ovflSize` is computed entirely in 32-bit unsigned arithmetic. When `nPayload` is near `0xffffffff`, the intermediate sum can wrap around, producing a much smaller `nOvfl` than the actual number of overflow pages. This under-sized value is then used to size and bound the overflow page cache (`aOverflow`), so later accesses like `pCur->aOverflow[iIdx]` and `pCur->aOverflow[iIdx+1]` can index beyond the allocated buffer, causing out-of-bounds memory access. The fix widens the computation to `i64` before dividing, preventing the overflow.
