## Bug Pattern

An input byte from a `parser_input` stream determines the number of continuation bytes consumed by a decode loop. The resulting loop counter is used as part of a bit-shift amount before an `aborting_assert`/upper-bound check ensures it is within the width of the shifted integer type. A crafted lead byte can therefore request too many continuation bytes and cause an out-of-range shift (undefined behavior); the bound check happens too late.

Roles:
- `parser_input`: `utf8_decode`, `iscont`
- `aborting_assert`: `lua_assert` (the missing/too-late invariant check; the fix places it before the shift)
