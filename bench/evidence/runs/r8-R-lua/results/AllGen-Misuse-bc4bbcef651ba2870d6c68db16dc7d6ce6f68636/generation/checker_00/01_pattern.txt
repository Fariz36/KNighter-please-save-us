## Bug Pattern

The bug pattern is **non-atomic publication of an object into a persistent registry**: a combined create-and-register operation (`luaL_newmetatable`) stores the new metatable in the registry **before** a separate fallible initializer (`luaL_setfuncs`) has completed. If that initializer raises/aborts due to a memory error, the incomplete object remains registered, so later lookups can observe a partially initialized metatable. The correct pattern is to separate lookup from creation, initialize the fresh object locally, and only register/publish it after all fallible initialization succeeds.

Roles:
- `persistent_registry_lookup`: `luaL_getmetatable`
- `combined_create_and_publish`: `luaL_newmetatable`
- `object_allocator`: `luaL_newlibtable`
- `object_initializer` that can raise/abort: `luaL_setfuncs`
- `registry_store` / `publish`: `lua_setfield(L, LUA_REGISTRYINDEX, BOXMT)`
- `registry_key`: `BOXMT` (`"_UBOX*"`)
